# GhostTrace v0.1.0

This is the first public release of GhostTrace, an explainable incident reconstruction platform built with FastAPI and React.

## Highlights

* **Import** JSON Lines, JSON or CSV (with field mapping). Every record is validated against a canonical event schema, with line-level errors, duplicate and conflicting-ID detection, and upload and record limits.
* **Correlation** links events through trace ancestry, request IDs and recorded dependency calls, including external services that emit no logs. Timing alone never creates a link.
* **Incident detection** uses Poisson burst tests to find error spikes, timeouts, retry storms, dependency failures, latency increases, deployment regressions and cascades. Each signal is labelled *observed* or *inferred*.
* **Root-cause hypotheses** come from six weighted signals minus contradiction penalties. Each hypothesis carries its evidence event IDs, uncertainty, missing information and a next step. When services aren't linked by evidence, the result is *insufficient evidence*.
* **Interactive views:** timeline, service graph, deterministic replay, healthy-versus-failed comparison, and verified JSON and Markdown reports.
* **Optional AI explanations** through Anthropic's SDK, with schema validation and evidence-ID checks. Off by default.
* **Single Docker image** serving the API and the UI, plus a compose file with an optional PostgreSQL profile and Render and Railway configs.

## Quality

* Backend: pytest suite with about 98% line coverage, strict mypy and Ruff.
* Frontend: Vitest and React Testing Library suite, ESLint, strict TypeScript.
* A Playwright end-to-end flow from import to report.
* A reproducible benchmark on held-out synthetic seeds. Results and caveats are in `benchmarks/README.md`.

## Known limitations

* No authentication.
* Evaluated on synthetic data only.
* False positives rise under heavy background error rates.
* Analysis is synchronous.
